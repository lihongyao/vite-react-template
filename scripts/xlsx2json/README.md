# XLSX 国际化语言包生成脚本

这个脚本将 `translations.xlsx` 中的翻译内容转换成应用使用的嵌套 JSON 语言包，输出目录为 `src/i18n/locales`。

脚本采用“源语言 + 目标语言”的维护方式。开发阶段只需要填写 `key` 和源语言文案，目标语言可以稍后由翻译人员补充。目标语言尚未翻译时，生成的 JSON 会自动使用源语言文案，避免页面显示空内容或翻译 key。

## Excel 格式

脚本读取 `translations.xlsx` 的 `Sheet1`，表头如下：

| key              | zh-CN              | en-US     | pt            | es            | remark   |
| ---------------- | ------------------ | --------- | ------------- | ------------- | -------- |
| profile.expired  | 会员已到期，请充值 |           |               |               | 会员提示 |
| profile.renewNow | 立即续费           | Renew now | Renovar agora | Renovar ahora | 按钮文案 |

各列用途：

- `key`：国际化调用使用的唯一标识，支持通过 `.` 生成嵌套对象，例如 `profile.expired`。
- `zh-CN`：当前配置的源语言，开发新增文案时必须填写。
- `en-US`、`pt`、`es`：目标语言，未完成翻译时可以留空。
- `remark`：可选备注，用于向翻译人员补充页面位置、业务含义等上下文，不会写入 JSON。

## 语言配置

源语言和目标语言在 `index.ts` 中显式配置：

```ts
const SOURCE_LOCALE = 'zh-CN';
const TARGET_LOCALES = ['en-US', 'pt', 'es'] as const;
```

只有配置中的语言会生成 JSON 文件。`key`、`remark` 或其他辅助列不会被当作语言处理。

## 生成规则

对于每个有效的 `key`：

1. 源语言 JSON 始终使用源语言单元格的内容。
2. 目标语言单元格有内容时，使用目标语言翻译。
3. 目标语言单元格为空时，使用源语言文案作为回退。
4. `key` 为空的行会被跳过。
5. `key` 有值但源语言为空时，脚本会报错并停止生成。

例如 `en-US` 尚未翻译：

```text
key: profile.expired
zh-CN: 会员已到期，请充值
en-US: （空）
```

生成的 `en-US.json` 中仍然会包含：

```json
{
  "profile": {
    "expired": "会员已到期，请充值"
  }
}
```

## 使用方式

在项目根目录执行：

```bash
pnpm i18n
```

脚本会：

1. 读取并验证 Excel 表头。
2. 验证每个有效 key 都有源语言文案。
3. 清空 `src/i18n/locales` 中已有的文件。
4. 生成源语言和所有目标语言的 JSON 文件。
5. 输出每种目标语言的已翻译数量和源语言回退数量。

`src/i18n/locales` 下的 JSON 是生成产物，不要直接修改；所有文案变更都应回到 `translations.xlsx` 中维护，然后重新执行命令。

## 日常维护

### 新增文案

1. 在 Excel 中新增一行。
2. 填写唯一的 `key`。
3. 填写 `zh-CN` 源文案。
4. 根据需要填写 `remark`，目标语言可以暂时留空。
5. 执行 `pnpm i18n`。

### 修改文案

直接修改 Excel 中对应单元格并重新生成。修改源文案后，尚未翻译的目标语言会自动使用新的源文案；已有目标语言翻译不会被覆盖。

### 新增目标语言

1. 在 Excel 表头新增语言列，例如 `ja`。
2. 将语言加入 `TARGET_LOCALES`。
3. 在 `src/i18n/config.ts` 中注册该语言。
4. 在 `src/i18n/resources.ts` 中导入生成的语言包。
5. 执行 `pnpm i18n` 并检查生成结果。

### 更换源语言

修改 `SOURCE_LOCALE`，并确保：

- Excel 中存在对应语言列。
- 每个有效 key 在该语言列中都有内容。
- 该语言没有同时出现在 `TARGET_LOCALES` 中。

## 文案注意事项

- 保持插值变量名称一致，例如 `{{point}}` 不应在翻译中改名。
- 保持富文本标签结构一致，例如 `<tag>{{point}}</tag>`。
- 单元格首尾空格会在生成时被移除。
- 目标语言确实需要显示为空字符串的场景不适合留空，因为空单元格表示“使用源语言回退”。
